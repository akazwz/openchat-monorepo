# Electron 客户端检查与验证记录

## 0.3.0：整体重写（2026-10-02）

用户要求重写这个客户端。0.1.x–0.2.2 的实现整体替换（那几版的逐项记录随旧实现一起移除）；下面是重写时确认的旧问题、新实现的做法，以及实际验证过和没验证的范围。

### 旧实现里确认的问题

| 问题                                         | 证据                                                                                                                                                                                                                                               | 新实现                                                                                                                                                                                   |
| -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 远程桌面连不上，页面只说“检查连接和权限”     | 屏幕采集走旧式 `getUserMedia({chromeMediaSource})`，媒体会话的权限检查只放行 `mediaType === "unknown"`；Electron 44 实测传来的是 `undefined`（临时脚本打印），这个条件永远不成立。Web 端收到 `remote_error` 后又把原因换成固定文案，看不出是哪一步 | 改用 Electron 文档推荐的 `getDisplayMedia` + `setDisplayMediaRequestHandler`，由主进程指定主显示器；会话结束的原因以代码传给观看者，Web 按原因给出说明（离线、缺哪项权限、有人在操作……） |
| 客户端自己的页面从 `file://` 加载            | 屏幕共享页和离线提示页都是 `file://`；打包时又关闭了 `GrantFileProtocolExtraPrivileges`                                                                                                                                                            | 自有页面从 `heveta-shell://` 提供：标准、安全的来源，只暴露列出的文件                                                                                                                    |
| 开发运行、本地联调和安装版共用一个配置目录   | `app.setPath("userData")` 固定为 `Heveta Electron`：开发二进制会读写安装版的登录、Keychain 条目和设备绑定                                                                                                                                          | 按“是否打包 × 连哪个服务”分开应用名、配置目录和 Keychain 条目                                                                                                                            |
| 任务日志只增不减                             | `journal/` 下每个命令一个文件，没有清理                                                                                                                                                                                                            | 启动命令进程时清掉七天前的记录（服务端的保留期）                                                                                                                                         |
| 同时执行的命令上限差一                       | `jobs.size > 8` 才拒绝，实际允许 9 个                                                                                                                                                                                                              | `>= 8`                                                                                                                                                                                   |
| 观看者按了不支持的键，会话被结束             | 任何输入错误都结束会话                                                                                                                                                                                                                             | 不认识的键跳过；只有辅助功能权限没了才结束                                                                                                                                               |
| 命令输出、文件读取可能截在一个字符中间       | 按字节截断后直接 `toString("utf8")`                                                                                                                                                                                                                | 截断处丢掉不完整的字符，`bytesRead` 按实际返回的字节算                                                                                                                                   |
| 工作目录是客户端的常量，和注册到服务端的无关 | 服务端按注册时的 `workspacePath` 放附件，客户端按当前常量解析相对路径                                                                                                                                                                              | 工作目录是绑定的一部分，绑定时定下（现在是 `~/Heveta`）；旧格式的绑定需要重新连接一次                                                                                                    |
| 标题栏                                       | 0.1.0 是 40 px 空白且不能拖动，0.1.1 换成系统标题栏                                                                                                                                                                                                | 窗口自己画一条与主题同色的窗口栏，可拖动，全屏时收起                                                                                                                                     |
| 一个文件管所有事                             | `device/host.ts` 同时管桥接、WebSocket、托盘、权限、执行；消息都是 `Record<string, unknown>`                                                                                                                                                       | 按职责拆分，协议消息有类型并在一处解析                                                                                                                                                   |

服务端配套：`StartRemoteDesktop` 被拒时返回原因（`ERROR_REASON_DEVICE_OFFLINE` 等四个），之前是抛一句英文。

### 实际验证（本机，macOS 27，Apple Silicon）

开发运行，连本地 `pnpm dev`（`http://localhost:5173`）：

- 窗口：启动、窗口栏与应用视图的位置（1220×820 的窗口：栏 36，视图 784）、浅色和深色下与侧边栏同色；菜单“设置”“新对话”经 Web 路由跳转且不重载；前进后退、缩放菜单项的可用状态。
- 加载失败：让页面加载一个连不上的地址，显示失败面板，缩放项禁用；点“重试”恢复。
- 设备：设置页点“连接”完成绑定，打开“允许访问”后上线（服务端日志有 `GET /device/connect 101`）；关掉再打开；带着访问退出，没有残留进程。
- agent 执行：在对话里选这台 Mac，模型依次调用 `shell`（写入并读出 `~/Heveta/electron-test.txt`）、`read_file`、`screenshot`（采集、上传，模型描述了画面）、`write_file`、`edit_file`（含中文和 emoji）、`send_file`（对话里出现文件卡片）、`release_input`。任务日志里每条都有结果。
- 远程查看：另一个浏览器打开设备的屏幕页，收到 2560×1440 的画面并在播放。

打包签名后的应用（未安装，从 `.build/packages` 启动，连本地服务）：

- 自有页面从 ASAR 里提供；命令进程从 ASAR 启动；屏幕录制和辅助功能权限随签名身份沿用（0.2.2 时已授权）。
- 远程操作：浏览器切到“操作”，发一个指针移动，本机指针从 x=2111.58 移到 2114.58（恰好 3 px）。原生模块、辅助功能和会话切换都走通。

构建检查：`tsc`、`oxlint`、`oxfmt --check`、打包后的签名校验。

### 没有验证的

- 键盘输入、点击、滚动、粘贴的远程注入（只测了指针移动，避免往正在用的桌面里乱输入）。
- 跨网络的连接：直连和 TURN 中继都只在本机回环上走过。
- 系统权限的首次申请弹窗（这台机器上两项权限都已授予）。
- 长时间运行、睡眠唤醒、断网重连、多个观看者、Intel 和 macOS 14。
- 线上服务：配套的 Web 和服务端改动上线之前，安装版连线上时，设备页和远控的错误说明还是旧的。

### 遗留

- 没有公证和自动更新；多显示器、系统音频、多窗口、退出后保留草稿都没做。
- 产品名仍是“Heveta Electron”，与 Swift 客户端并存；哪个作为正式的桌面版、是否改名，待定。
